Import Validation & Unified Tree-Sitter Extraction — Implementation Plan
=========================================================================

GOAL: Move all import parsing to tree-sitter (via LSP worker), move all
import resolution + file collection + external fetching to the main thread,
make the render worker a dumb VM executor, and add red squiggles for
unresolvable imports as a natural side effect.


PHASE 1: LSP "extractImports" capability
-----------------------------------------

1a. Add types to scadLspProtocol.ts:

    ScadImport {
      kind: "include" | "use" | "import" | "surface"
      path: string                    // raw path from source
      startLine, startColumn          // position of the FULL statement
      endLine, endColumn
      pathStartColumn, pathEndColumn  // position of just the path string
    }

    New request:  { type: "extractImports", id, text }
    New response: { type: "importsResult", id, imports: ScadImport[] }

1b. Add AST walker to scadLsp.worker.ts:

    function extractImportNodes(root: SyntaxNode): ScadImport[]
      - Walk root.namedChildren for `include_statement`, `use_statement`
        → child `include_path` gives path text + positions
      - Walk root.descendantsOfType("function_call")
        → if function identifier is "import" or "surface",
          grab first string argument's text (strip quotes)
      - Return structured array with positions

1c. Add client method to scadLspClient.ts:

    extractImports(text: string): Promise<ScadImport[]>


PHASE 2: Main-thread import collection (replace regex-based collectImports)
---------------------------------------------------------------------------

2a. Rewrite collectImports() in importUtils.ts:
    - Accept the LSP client as a parameter
    - For each file's text, call lspClient.extractImports(text) instead of
      extractImports()/extractStlImports() regex
    - Same recursive walk logic, same FSA lookups, same external set
    - Also detect import("...") for ALL geometry types, not just .stl
    - Also detect surface("...") references

2b. Move external file fetching from the render worker to main thread:
    - After collectImports, fetch all absolute external paths (currently done
      by addExternalFiles in the worker)
    - Recursively scan fetched .scad files for their own imports
      (can use lspClient.extractImports on fetched text too)
    - Return the complete set: { projectFiles, externalFiles, allResolved }

2c. Move path rewriting to main thread:
    - rewriteProjectImportsForVm() currently runs in the worker using regex
    - Replace with a tree-sitter-aware rewriter: use the ScadImport positions
      to do precise string surgery (replace path at known offsets)
    - Rewrite all collected file contents before sending to worker
    - The main file's source code also gets rewritten here

2d. New render worker interface:
    - Instead of sending { extraFiles, externalImports } and letting the
      worker figure it out, send a flat { vmFiles: Record<string, string|Uint8Array> }
      that maps VM paths → already-rewritten content
    - Worker just does: for each entry, writeFileWithDirs(fs, vmPath, content)
    - Worker no longer imports extractImports, extractStlImports,
      collectAbsoluteImportsFromCode, rewriteProjectImportsForVm, etc.
    - Worker no longer calls fetch() for external files

    This means RenderRequest changes:
      REMOVE: extraFiles, externalImports
      ADD:    vmFiles: Record<string, string | Uint8Array>
              vmMainPath: string   (already-computed VM path for the entry file)


PHASE 3: Red squiggles (diagnostics)
-------------------------------------

3a. Add a new hook or extend useOpenSCADLsp: useImportDiagnostics()
    - On code change (debounced), call lspClient.extractImports(text)
    - For each returned ScadImport, attempt resolution:

      RELATIVE (no prefix):
        → resolveImportPath(currentFile, path)
        → Check if resolved path exists in project file tree
        → SQUIGGLE if not found, message: "File not found: <resolved>"
        EXCEPTION: bare "MCAD/..." → always valid (OpenSCAD library search)

      @/ PREFIX:
        → Strip @/, resolve from project root
        → Check project file tree
        → SQUIGGLE if not found

      / PREFIX (absolute):
        → /libraries/MCAD/... → always valid
        → /fonts/... → always valid
        → Other /... → async HEAD fetch to check existence
        → SQUIGGLE if 404, message: "External file not found: <path>"

    - Push diagnostics to Monaco via editor.setModelMarkers()
    - Squiggle range = the path portion of the import (pathStart → pathEnd)

3b. Project file tree:
    - We need a quick way to check "does this relative path exist?"
    - Options:
      a) Use the file tree already built by FileBrowser (it walks the directory)
      b) Try/catch on getFileHandleFromPath (already what collectImports does)
      c) Maintain a Set<string> of known project paths, updated on file tree refresh
    - Option (c) is cleanest for synchronous checks; (b) is simplest


PHASE 4: Cleanup
-----------------

4a. Remove from importUtils.ts:
    - extractImports() (regex)
    - extractStlImports() (regex)
    - Keep: normalizePathParts, normalizeAbsolutePath, resolveImportPath,
      toVmProjectPath, resolveProjectImportPathForVm (still needed for resolution)

4b. Remove from openscad.worker.ts:
    - collectAbsoluteImportsFromCode()
    - resolveAbsoluteImportPath()
    - addExternalFiles() + grabExternalFile()
    - addExtraFiles() (replaced by simple vmFiles write loop)
    - Imports of regex extraction functions

4c. Remove rewriteProjectImportsForVm() regex version from importUtils.ts
    (replaced by position-based rewriter in Phase 2c)
